# Team Planner Power App: build kit

Everything needed to build the SharePoint version of the Team Planner in Power Apps:

| File | What it is |
| --- | --- |
| `screens/01-scrToday.yaml` … `13-scrMyRequests.yaml` | One file per screen. Each holds a single container with the whole screen inside, for **Paste code**. |
| `App.Formulas.txt` | Paste into the App object's **Formulas** property: the status colours, cadences and pick lists. |
| `App.OnStart.txt` | Paste into the App object's **OnStart** property: loads the roster, tasks and your settings. |
| `OnVisible.txt` | Formulas for four screens' **OnVisible** property. They clear the form inputs each time the screen opens. |
| `flows.md` | Click-by-click build steps for the two PTO flows. |

The design these implement is in [../sharepoint-migration-plan.md](../sharepoint-migration-plan.md).
The files are generated by `scripts/generate-power-app.mjs`. Change the generator and
re-run it rather than editing the YAML by hand, so all thirteen screens stay
consistent.

## Before you build

The YAML uses the **updated modern controls** (`ModernText@1.0.0`, `ModernButton@1.0.0`
and so on, released February 2026). Their property names differ from most examples
online: `Color` rather than `FontColor`, and `Size` rather than `FontSize`. Every
formula has been run through Microsoft's Power Fx parser. The YAML matches Microsoft's
published schema, and every property is one Microsoft documents for that control. What
couldn't be checked without Power Apps itself is whether Studio accepts every paste.
If a paste is rejected, send me the error message and the file name, and I'll fix the
generator and regenerate.

## Build order

### 1. SharePoint (plan §3 and §7)

Create the site, set its time zone, and import the five CSVs. Then create **TP PTO
Requests** and **TP Settings** by hand, add the indexes, and set the permissions. On
TP People, fill in **Person**, **Approver** and **Admin** for everyone active.

### 2. Flows

Build **TPSubmitPTORequest** and **TPCancelPTORequest** from [flows.md](flows.md), under
your account. Build them before the app: the app can only add a flow that already
exists.

### 3. The app shell

1. Go to make.powerapps.com and choose **Create** → **Start with a blank canvas** →
   **Tablet size**. Name it `Team Planner`.
2. Under **Settings** → **General**, set **Data row limit** to `2000`.
3. Under **Settings** → **Updates**, make sure **Modern controls and themes** is on, if
   it's listed. Without it, every paste fails with an unknown control type.
4. Under **Settings** → **Display**, leave **Scale to fit** on. The screens are laid out
   for 1366 × 768 and scale from there.
5. In **Data** → **Add data**, choose **SharePoint**, then your site, and tick all
   seven lists: TP People, TP Entries, TP Tasks, TP Task Done, TP Milestones, TP PTO
   Requests and TP Settings. Then add **Office 365 Users** and **Office 365 Outlook**.
6. In the **Power Automate** pane (left rail, or **…** → Power Automate), choose **Add
   flow** and add both flows.

### 4. App formulas

1. In the Tree view, select **App**. Choose the **Formulas** property and paste all of
   `App.Formulas.txt`.
2. Choose the **OnStart** property and paste all of `App.OnStart.txt`.
3. Select **App** → **…** → **Run OnStart**, so the variables exist while you build.

### 5. Screens

1. Create the screens first, all of them, with these exact names. Rename Screen1 to
   `scrToday`, then use **New screen** → **Blank** for the rest. Formulas navigate
   between screens by name, so a missing screen shows as an error until you create it.

   | File | Screen name | What it is |
   | --- | --- | --- |
   | 01 | `scrToday` | Who's out today, this week, recurring tasks in play, birthdays |
   | 02 | `scrMyTasks` | Your duties grouped by when they're due, with ticking and tags |
   | 03 | `scrTaskCalendar` | Every task, filterable, as a list or by month. Prebuilt-screen layout. |
   | 04 | `scrWhereabouts` | The team month calendar, including pending PTO. Prebuilt-screen layout (Header and gallery). |
   | 05 | `scrEntryDetail` | One entry: visit, notes, hotel and flight |
   | 06 | `scrEntryEdit` | Add or edit an entry |
   | 07 | `scrTaskEdit` | Add or edit a task (tags only for assigned work) |
   | 08 | `scrPrint` | Month or quarter grid plus rollup, for printing |
   | 09 | `scrMyEntries` | Bulk delete of your own entries |
   | 10 | `scrRoster` | Admin: sign-ins, approvers, admin/active, remove |
   | 11 | `scrSiteCircuit` | The monthly leadership visit email |
   | 12 | `scrRequestPTO` | Request PTO. Prebuilt-screen layout (Approval request). |
   | 13 | `scrMyRequests` | Your PTO requests, with withdraw and cancel |

2. Paste each file onto its screen:
   1. Open the `.yaml` file on GitHub, select **Raw**, select all, and copy.
   2. In Power Apps, right-click the screen in the Tree view and choose **Paste code**.
      Ctrl+V with the screen selected works too. The first paste asks for clipboard
      access; allow it.
   3. A container named like `tdyRoot` appears, filling the screen.
   Files 03, 04 and 12 use the layout of Power Apps' prebuilt responsive screens
   (**New screen** → *Header and gallery* / *Approval request*): a screen container,
   a header container with the modern **Header** control, and a main container of
   cards. The YAML builds that whole layout itself, so paste it onto a blank screen.
   If you start from the prebuilt screen instead, delete its `ScreenContainer1`
   first, then paste. The prebuilt Approval request form isn't kept, because it
   writes straight to a list; PTO requests go through the approval flow instead.
3. Set **OnVisible** on the four screens listed in `OnVisible.txt`: `scrEntryEdit`,
   `scrTaskEdit`, `scrRequestPTO` and `scrMyEntries`.
4. Select **App** and set **StartScreen** to `scrToday`.

### 6. Look and feel

Modern controls take their colours from the app theme. Under **Themes**, create a
custom theme with the base colour `#0053a1` (Rotech blue) so buttons and pickers match.
The status colours, such as green for PTO and blue for site visits, are fixed in
`App.Formulas.txt` and don't depend on the theme.

### 7. Publish and share

Save, then publish. Share the app with the team; they also need to be **Members** of the
SharePoint site. Add it as a tab in the team's Teams channel, or link it from the
survey-prep app at cutover (plan §8).

## What to expect while building

- **Red errors right after a paste** usually mean something the formulas refer to
  doesn't exist yet: a screen, a list, a flow or `varMe`. They clear once everything is
  in place and OnStart has run. Anything still red after that is worth sending me.
- **Blue delegation warnings** on formulas over the small lists (TP People, TP Tasks,
  TP Milestones) are expected and harmless. Those lists are loaded into collections,
  and each is far under the 2,000-row limit. A warning on a **TP Entries** filter is
  not expected: every calendar query filters on the number columns StartNum and EndNum
  so SharePoint can run it. Tell me if you see one.
- **Checkbox-style controls** are tappable ☐ / ☑ text rather than modern Checkbox or
  Toggle controls. Microsoft hasn't documented the YAML names for the updated versions
  of those two, and a wrong control name would fail the whole paste.

## Names the formulas rely on

If you rename any of these, update the formulas that use them, or ask me to regenerate.

- **Lists:** `TP People`, `TP Entries`, `TP Tasks`, `TP Task Done`, `TP Milestones`,
  `TP PTO Requests`, `TP Settings`. Their columns are in plan §3.
- **Flows:** `TPSubmitPTORequest` and `TPCancelPTORequest`. Their inputs and outputs
  are in flows.md.
- **Variables:**
  - `varMe`: your TP People row
  - `varIsAdmin`: from the Admin column
  - `varAnchor`: the month in view
  - `varEntry` and `varTask`: the record being viewed or edited
  - `varNewDate`
  - `varTaskTeam`
  - `varSettings`
- **Collections:** `colPeople`, `colTasks`, `colMilestones`, `colDone`, `colSel`.
- **Named formulas:** `nfStatus`, `nfCadences`, `nfMonths`, `nfLeaveTypes`,
  `nfDayParts`, `nfVisitModes`, `nfConfirmations`.
